An AsciiDoc[tor]-powered wiki of sorts.

== Local Development

=== Dependencies

Install the dependencies:

[,shell-session]
----
$ cd ./adocwiki
$ gem install bundler
$ bundle install
----

Then, go to your wiki/docs directory:

[source,shell-session]
----
$ cd path/to/docs/with/nav.yml
$ ruby path/to/adocwiki/src/main.rb $PWD
----

=== Local Webserver

Then run some webserver in the `./build/` directory.
Python3 has a nice quicky and easy http module:

[,shell-session]
----
$ python3 -m http.server -b localhost 3001
Serving HTTP on ::1 port 3001 (http://[::1]:3001/) ...
----

Then, open the browser at link:http://localhost:3001/[localhost:3001].

=== Unit Tests

[source,shell-session]
----
$ bundle exec rspec --format=documentation ./some_module.spec.rb
----

Or the short options:

[source,shell-session]
----
$ bundle exec rspec -f d ./some_module.spec.rb
----

Or for all spec files:

[source,shell-session]
----
$ bundle exec rspec -f d ./*.spec.rb
----

== Assets

[NOTE]
====
The commands below is a temporary workaround until a better, more automated approach is implemented.
====

On every AsciiDoc file, set the `imagesdir` attribute to `__assets` and make sure to create a directory `__assets` as a sibling of the document which will include those assets.

Then include the image like this:

.Example
[source,asciidoc]
----
= Document Title
:icons: font
:sectlinks:
:sectlevels: 6
:imagesdir: __assets

== Intro

Intro text...

image:my-image.png[Alt text]
----

After building (converting to HTML) the documents, copy the assets to each sub-directory inside the `build/` directory accordingly (assumes bash >= 4):


[source,bash]
----
assets_dir=($(find ./docs -type d -name __assets -print))

for asset_dir in "${assets_dir[@]}"
do
  cp -rv "$asset_dir" "${asset_dir/docs/build}"
done
----

== Page titles and other attributes

The `= Title` is used for both the page title shown at the top of the document, as well as the title that goes inside the `<title>` HTML tag and shows in the browser tab.

=== page-title

The title that shows in the browser URL.
Defaults to `= Title`.
It means, it is possible to use `= Title` inside the document, and use `page-title` to override what is used inside `<title>` tag.

=== page-subject

Appended after `= Title` or `page-title` in inside the `<title>` tag of the page.
It helps users and SEO.

For example, suppose we have a page in `docs/cmdline/intro.adoc`.
We can have something like this in the file:

[source,asciidoc]
----
= Bash
:page-subject: Command Line

== Getting started

Hello, World!
----

It renders as:

[source,html]
----
<head>
  <title>Bash :: Command Line :: Dev How To</title>
</head>

<body>
  <h2>Getting Started</h2>
  <p>Hello, World!</p>
</body>
----

Or, using `page-subtitle` to override `= Title`:

[source,asciidoc]
----
= Bash
:page-title: Bash (Bourne-Again SHell)
:page-subject: Unix Command Line

== Getting started

Hello, World!
----

Renders as:

[source,html]
----
<head>
  <title>Bash (Bourne-Again SHell) :: Unix Command Line :: Dev How To</title>
</head>

<body>
  <h2>Getting started</h2>
  <p>Hello, World!</p>
</body>
----
